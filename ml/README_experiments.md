# 实验记录与模型选择（baseline vs improved）

本文件记录本项目胜负预测模型的实验设计、对比结果与上线选择。
所有实验均由 `ml/train.py` 驱动，参数、指标、数据版本、代码提交都完整记录在 MLflow。

## 实验目标

在**相同的时间外推测试集**上，比较一个朴素基线模型与一个改进模型，
验证特征工程与模型升级是否真正提升预测效果，**以 F1 为主要判据**（同时兼顾 accuracy）。

## 评估口径

- **数据**：`match_stats_v2.csv`（DVC md5 `b7c62be3…`，data-v2 标签），共 21,136 场。
- **划分**：严格按时间顺序，**不随机打散**。前 80% 为训练集（16,908 场，2007–2023.09），
  最近 20% 为测试集（4,228 场，2023.09–2026.07）。这样测试集是模型真正"未来"的比赛，
  避免用同年代数据训练又测试造成的乐观偏差。
- **指标**：accuracy、precision、recall、F1；标签为 team1 是否获胜。

## 关于 baseline / improved 的设计说明

v1 原始数据只有比分、选手名等**文本结果字段，没有任何可直接建模的特征**，
所有模型（含基线）都必须在 v2 工程特征上训练。因此两个模型的差异不是"v1 对 v2"，而是：

- **baseline：逻辑回归（3 个朴素特征）**——仅用 `elo_diff`、`at_home_1`、`at_home_2`，
  代表"只看一个 Elo 分差 + 主场"的最简单模型。
- **improved：随机森林（13 个全部特征）**——加入历史胜率、近期状态、交手记录、
  场均局点差、历史局胜率等，并对森林深度与叶节点做超参调优。

这样对比能干净地回答："**在同样的 Elo 基础上，增加多维历史特征并使用更强的模型，
能否带来额外收益？**"

## 实验结果

| run 名称 | 模型 | 特征数 | accuracy | precision | recall | F1 |
|----------|------|------|----------|-----------|--------|------|
| `baseline_logistic_elo` | 逻辑回归（标准化，C=1） | 3 | 0.6649 | 0.6594 | 0.6641 | 0.6617 |
| `improved_rf_d10_l20` | 随机森林 300/深度10/叶20 | 13 | 0.6705 | 0.6709 | 0.6526 | 0.6616 |
| `improved_rf_d12_l10` | 随机森林 300/深度12/叶10 | 13 | 0.6717 | 0.6704 | 0.6588 | **0.6646** |

（两个随机森林为不同超参的独立 run，用于体现调参过程；`max_features=sqrt`，`random_state=42`。）

## 模型选择：`improved_rf_d12_l10`

该 run 在全部四项指标上达到或接近最优，被注册为生产模型：

- **F1 = 0.6646，高于 baseline 的 0.6617**，满足"改进模型 F1 不低于基线"的要求。
- accuracy = 0.6717，高于 baseline 的 0.6649（约 +0.7 个百分点）。
- precision = 0.6704，recall = 0.6588，相比 `d10_l20`（recall 0.6526）更均衡，
  整体 F1 更高。
- 已注册为 `badmin-win-predictor` v1 并打 `production` 别名。

## 为什么提升幅度不大（结果的客观分析）

- 比赛胜负**高度由双方实力（Elo）决定**：仅用 Elo 分差阈值在最近赛季即可达到约 66.5%
  的准确率，这已经接近该任务的"天然可预测上限"。
- 羽毛球多数比赛为中立场地，主客场几乎无影响；爆冷、临场状态、伤病等因素
  不含在历史数据中，构成剩余的不可约误差。
- 因此额外特征只能带来小幅但稳定的增益，这是真实数据的客观结论，
  也说明继续堆叠同类历史统计特征收益有限——若要进一步突破，需引入
  近期赛程密度、选手打法/伤病、BWF 实时积分（高匹配率）等新信息源。

## 如何复现

```bash
# 1. 同步数据（需要 Azure 连接串，找成员 C）
dvc pull

# 2. 重新生成 v2 特征
python ml/registry/data_pipeline.py

# 3. 一键跑完 baseline + 两个 improved run，并注册最佳模型
python ml/train.py --all

# 4. 导出生产模型到 models/
python ml/export_model.py

# 5. 校验 MLflow 记录、注册与加载
python ml/verify_tracking.py

# 或查看 MLflow 界面
mlflow ui --backend-store-uri sqlite:///mlruns/mlflow.db
```
